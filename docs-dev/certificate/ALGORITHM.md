# Генерация сертификата участника — алгоритм для разработчиков

Механика соответствует тому, как это делается в Академии: **фон сертификата
загружается как JPG, тексты формируются скриптом (разметка HTML + CSS)**,
результат печатается в PDF и уходит вложением в письмо.

## Состав пакета (docs-dev/certificate/)

| Файл | Назначение |
|---|---|
| `certificate-bg.jpg` | Фон сертификата, 5834×4125 px (300 dpi из исходного PDF оргкомитета «Сертификат Диктант v3 ИТОГ (3).pdf»), 297×210 мм альбомная. |
| `certificate-template.html` | HTML/CSS-шаблон: фон + позиционированные текстовые поля. Именно его печатает скрипт. |
| `fields.json` | Машинное описание полей: координаты (px и на печати), шрифт, цвет, маски. Единый источник правды для генератора. |
| `fonts/Unbounded-Medium.ttf`, `fonts/Manrope-SemiBold.ttf` | Шрифты макета (предоставлены дизайнером). Подключены в шаблоне через `@font-face` относительными путями – переносить вместе с папкой `fonts/`. |
| `ALGORITHM.md` | Этот документ. |
| `certificate-demo.pdf` | Демонстрационный результат (Иванова Мария Сергеевна, 27/30, ПА/НОТА-26/000001). |

## Шаг 1. Исходник фона

Фон один раз экспортируется из PDF оргкомитета:

```bash
# Python + PyMuPDF
python3 -c "import fitz; d=fitz.open('Сертификат ИТОГ.pdf'); \
  p=d[0].get_pixmap(dpi=300); p.save('certificate-bg.jpg', jpg_quality=90)"
```

В бою оргкомитет может прислать фон **без слов-плейсхолдеров**
(«Фамилия Имя Отчество», «XX», «XXXXXX»). Тогда шаблон используется
с классом `clean` — маски-заплатки не рендерятся вообще.
Если фон с плейсхолдерами — маски компенсируют их (см. `coverPlaceholder`
в fields.json): это прямоугольники в цвет фона (`#fbfcf7` справа,
`#0d2a66` слева), поверх которых ложатся настоящие значения. У
регистрационного номера маска закрывает **только `XXXXXX`**: напечатанный
на фоне префикс `ПА/НОТА-26/` остаётся, а генератор рисует после него
только шесть цифр.

## Шаг 2. Данные участника

После регистрации (POST /api/register) сервер знает:

```json
{
  "surname": "Иванова", "name": "Мария", "patronymic": "Сергеевна",
  "score": 27, "regNumber": "ПА/НОТА-26/000001"
}
```

API и база хранят полный регистрационный номер: `ПА/НОТА-26/` + ID
участника. Генератор извлекает ID, дополняет его нулями слева ровно до
6 знаков и в поле `regnum` подставляет **только эти 6 цифр без
префикса**. Префикс `ПА/НОТА-26/` уже напечатан на фоне сертификата.

## Шаг 3. Рендер в PDF

Скрипт подставляет значения в `span[data-field]` шаблона и печатает
страницу в PDF размером ровно 297×210 мм:

```bash
chromium --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf=certificate-000001.pdf \
  "certificate-template.html?fio1=Иванова&fio2=Мария&fio3=Сергеевна&score=27&regnum=000001"
```

Внутри шаблона уже заложены `@page { size: 297mm 210mm; margin: 0 }`,
так что PDF получается без полей и колонтитулов — ровно по макету.

Тот же принцип из PHP/Bitrix: рендер через headless-браузер
(chromium/chrome, wkhtmltopdf, dompdf *не* рекомендуем — точность
хуже) либо через headless-инстанс на стороне сервера писем.

## Шаг 4. Контроль качества

1. **Шрифты макета** (указаны дизайнером): ФИО – Unbounded Medium,
   кегль 40 px при 150 dpi (≈19 pt); итоговый балл – Unbounded Medium,
   100 px (≈48 pt); регистрационный номер – Manrope SemiBold,
   15 px (≈7 pt). TTF-файлы лежат в `fonts/` и подключены через
   `@font-face` – проверить, что они встроились в PDF
   (в Acrobat: Свойства → Шрифты).
2. **Переполнение**: если ФИО длиннее ~24 символов, уменьшать размер
   шрифта до влезания строки (в fields.json — одна строка на поле).
3. Отчество может отсутствовать — поле `fio3` тогда пустое, вёрстка
   не сдвигается.
4. Итог PDF — одна страница, 297×210 мм, ≤1,5 МБ (jpg-фон).

## Отправка письма с сертификатом (с почты оргкомитета)

Письмо уходит участнику **в течение 48 часов после прохождения
диктанта** с официального почтового ящика оргкомитета проекта.
Генератор сертификата сам письма не шлёт – это отдельный серверный
агент. Схема конвейера на сервере Академии (1С-Битрикс):

```
/ POST /api/register (участник отправил форму, получил ПА/НОТА-26/000123)
        ↓  запись попадает в очередь «Сертификаты к отправке» (таблица/инфоблок)
АГЕНТ БИТРИКСА (cron, раз в 10–15 минут; CAgent::AddAgent):
  1. берёт новые регистрации без флага «сертификат отправлен»;
  2. генерирует PDF: headless Chromium печатает certificate-template.html
     с подставленными ФИО/баллом/рег. номером (шаги 1–3 выше);
  3. отправляет письмо ЧЕРЕЗ ПОЧТУ ОРГКОМИТЕТА:
       – штатно: почтовое событие Битрикса (CEvent::Send) с вложением,
         а в настройках главного модуля подключён SMTP официального
         ящика оргкомитета (например diktant2026@ranepa.ru) –
         тогда письмо уходит именно «с почты оргкомитета» с валидными
         DKIM/SPF домена ranepa.ru;
       – альтернатива: прямой SMTP-клиент (PHPMailer) на тот же ящик;
  4. помечает регистрацию «сертификат отправлен» (+дата, +ID письма).
```

Контроль SLA 48 часов: у агента метрика «возраст» записи в очереди;
старше 48 ч — уведомление администратору. Ошибки доставки (bounce)
падают обратно в ящик оргкомитета — их разбирает человек.

Запасной ручной вариант: из админки (список регистраций) можно
одной кнопкой сгенерировать PDF и скачать его, а веб-версия ящика
оргкомитета отправит письмо вручную — алгоритм генерации тот же.

Текст письма оргкомитет редактирует в CMS (почтовый шаблон события /
шаблон в Битриксе), согласованный вариант — CMS-GUIDE.md.
