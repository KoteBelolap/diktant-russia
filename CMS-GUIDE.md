# CMS-GUIDE — перенос и управление сайтом диктанта в 1С-Битрикс

Документ для команды разработки Президентской академии. Описывает, как
устроен текущий статический прототип и как перенести его в раздел
корпоративного сайта на 1С-Битрикс, сохранив все возможности редакционного
управления.

> **Обновление от заказчика:** рассматривается и вариант **отдельного сайта**
> (не раздела академии). Проект сразу спроектирован так, чтобы работать в
> обоих режимах — см. раздел 2. Решение по размещению не потребует
> переделки кода.

## 1. Что здесь лежит

```
/                       – статические страницы (index, materials, news,
                          article, test, register)
/assets/css/style.css   – единая дизайн-система «Liquid Glass»
/assets/js/             – скрипты (см. таблицу ниже)
/assets/img/            – изображения (в бою — из инфоблоков/медиабиблиотеки)
/assets/fonts/          – Unbounded + Manrope (woff2, кириллица+latin)
/docs-dev/              – материалы для разработчиков (не для публики):
    certificate/        – пакет генерации сертификата (фон, шаблон, JSON,
                          алгоритм, демо-PDF)
    documents/          – Word-документы оргкомитета (контент-предложения,
                          архив правок)
README.md               – общее описание, API-контракты
CMS-GUIDE.md            – этот файл
```

Скрипты фронтенда:

| Файл | Роль |
|---|---|
| `config.js` | **Настройки проекта** (даты старта/финиша, режим тренировочных тестов, тексты гейт-плашек) + синхронизация времени с сервером. Единственное место, где меняются даты. |
| `gate.js` | «Серая кнопка» до старта и блок тренировочных тестов. Работает от `data-gate`-атрибутов. |
| `typograf.js` | Авто-Nbsp после предлогов/союзов (1–3 буквы): невисячие строки. |
| `news-data.js` | Источник новостей/статей/видео **для статики**. В бою заменяется выдачей CMS (формат идентичен). |
| `main.js` | Общие механики: отсчёт, бегущая строка, карусель+лайтбокс, счётчики, графики, FAQ, плавающая CTA. |
| `test.js` | Механика теста: гейт дат, 30-из-банка, перемешивание, таймер, History API, результат, встраивание формы регистрации. |
| `reg-form.js` | Единый модуль регистрационной формы (test.html и register.html): валидация, поиск организации, дубль-проверка, экран успеха. |
| `register.js` | Тонкая прослойка отдельной страницы register.html. |
| `question-bank-demo.js` | ⚠ **КАРАНТИН. Демо-банк вопросов только для превью. НЕ выкладывать в бой** — правильные ответы в нём. |
| `assets/data/orgs/*.json` + `tools/xlsx-to-orgs.py` | Полный справочник организаций (~66 тыс.) из официального Excel `docs-dev/reference/orgs-source.xlsx` (обновление: положить новый .xlsx и запустить конвертер). Поиск глобальный по всем субъектам с бонусом своего региона (иногородние студенты); зарубежные школы участвуют в поиске «на всякий случай». Тип участника «Иные организации» использует тот же справочный поиск (подпись поля на клиенте – «Наименование организации»; рассылка по консульствам – генконсульства и школы при посольствах в справочнике есть), чего нет в списке – ручной ввод по галочке. В бою заменяется `/api/orgs` с тем же поведением, куда импортируется тот же Excel. |

## 2. Размещение

> **Решение оргкомитета: единственный вариант — раздел сайта Академии
> ranepa.ru** (например `ranepa.ru/diktant-2026/`). Отдельный сайт/поддомен
> не делается (см. примечание 2.2 в конце раздела).

### 2.1. Раздел сайта Академии ranepa.ru (единственный сценарий)

Страницы диктанта встраиваются в шаблон сайта Академии как **содержимое
области контента**. Всё «хромовое» (шапка/подвал Академии) остаётся
штатным, а диктант-панели (полоса разделов сверху/снизу, футер проекта)
сделаны **отключаемым слоем**:

- Вёрстка полос — `.topnav` и `.footnav`, собственный футер — `.footer`.
- Все стили диктанта изолированы префиксными классами и CSS-переменными
  в начале `style.css`; конфликтов с глобальными стилями Академии нет
  (сброс рамок `box-sizing` scoped, без `*`, без переопределения `body`
  кроме шрифта и фона внутри `.app`-обёртки).
- Подключение: в шаблоне раздела подключаются `style.css` + скрипты из
  таблицы выше; контент страниц — инфоблоки (раздел 3).

**Чек-лист интеграции раздела:**
1. Создать раздел сайта (например `/projects/diktant-2026/`).
2. В шаблоне раздела вывести мета-тег серверного времени (раздел 4).
3. Подключить стили/скрипты проекта (относительные пути — работают
   из любого уровня вложенности).
4. Завести инфоблоки раздела 3 и вывести их как у страниц прототипа.
5. Настроить серверные обработчики раздела 5 (тест, регистрация, письма).

### 2.2. Примечание (не используется)

Технически прототип автономен и мог бы работать отдельным сайтом:
достаточно вынести его на свой домен/поддомен и заменить относительные
`assets/…` на абсолютные. **По решению оргкомитета этот сценарий не
применяется — проект размещается только разделом ranepa.ru.**

## 3. Редакторское управление (инфоблоки)

Каждый видимый блок прототипа — инфоблок или список. Формат полей
один-в-один совпадает со структурой JS-данных прототипа, поэтому шаблоны
вывода почти не меняются.

### 3.1. Новости (`NEWS_DATA` → инфоблок «Новости диктанта»)

Поля элемента:
```
id/code    slug (для ссылки article.html?id= → ЧПУ /news/slug/)
date       дата публикации (формат дд.мм.гггг)
cover      картинка-обложка (JPG, 4:3, ≥1200px)
title      заголовок новости
excerpt    анонс (1–2 предложения)
body[]     массив абзацев полного текста (HTML из визреда: <p>, <strong>)
```
Поведение: на главной автоматически выводятся **2 последние по дате**
одной строкой + кнопка «Все новости». Если элементов нет — показывается
плашка «Нет актуальных новостей» (в бою блок просто не выводится).
Карточки приподнимаются при наведении (заложено в CSS).

### 3.2. Статьи и видеолекции (`ARTICLES_DATA`, `VIDEOS_DATA`)

Та же структура + у видео поле `dur` (хронометраж) и `file` (mp4 H.264,
≤30 МБ). Видео лучше держать в медиабиблиотеке Битрикса или на
видеосервере Академии, отдавая прямые mp4-ссылки.

Поведение пустой ленты — как у новостей: пока статей нет, на странице
«Материалы для подготовки» автоматически показывается плашка
«Статей пока нет – материалы для подготовки появятся здесь позже»
(в бою блок просто не выводится). Статьи открываются той же страницей
`article.html?id=…` (поиск сначала в `ARTICLES_DATA`, затем в `NEWS_DATA`).

Интеграция в Битрикс: инфоблок «Статьи диктанта» с теми же полями, что
у новостей (см. 3.1) — шаблон вывода `article.html` общий.

### 3.3. Медиа-лента на главной (карусель)

Элемент = { фото (JPG, 3:2, ≤600 КБ), подпись `data-caption`, порядок }.
Количество и порядок слайдов — сортировкой инфоблока.

### 3.4. Обращения (цитаты), гости, партнёры, FAQ, контакты

- **Цитаты**: текст, автор, регалии, фото (круг, webp 240×240). Первая —
  акцентная (крупнее): флаг «главная».
- **Почётные гости**: имя, регалии, фото (webp 240×240).
- **Партнёры/организаторы**: логотип (png/svg, прозрачный), название,
  ссылка, флаг крупного (Академия — самая крупная плитка).
- **FAQ**: вопрос, ответ (HTML; текущий вербатим про сертификат см. в index.html).
- **Контакты**: ФИО, роль, e-mail, фото (webp 360×360).

### 3.5. Фотография баннера

Правый коллаж хиро — элементы инфоблока (фото + порядок + подпись).
Сейчас витринные фото лежат в `assets/img/media/`.

## 4. Настройки проекта (инфоблок «Настройки» или параметры раздела)

Отражение `config.js` → поля настроек:

| Настройка | Значение по умолчанию | Описание |
|---|---|---|
| `startDate` | `2026-11-05T10:00:00+03:00` | Старт диктанта |
| `endDate` | `2026-11-08T23:59:59+03:00` | Окончание |
| `trainingMode` | `off` | Тренировочные тесты: `off` (скрыты, плашка «появятся позже») / `on` (видны). Авто-открытия по дате НЕТ — включение только вручную (запрос заказчика 08.08.2026): когда учебные вопросы подготовлены в CMS, ставим `on`. |
| `certDecisionSec` | `120` | Сколько секунд экран результата ждёт выбора «Дозаполнить данные»/«Отказаться», затем ответ пишется в базу без ФИО («не заполнено») |
| `testUrl` | `test.html` | Адрес страницы прохождения |
| `gateCaption` | «Диктант начинается 5 ноября в 10:00 по московскому времени» | Подпись под серой кнопкой |

**КРИТИЧНО — серверное время.** Старт должен наступать по часам сервера
в Москве, а не устройства пользователя. Шаблон раздела обязан отдавать:

```html
<meta name="server-time" content="2026-11-01T12:34:56+03:00">
```

(`date('c')` на PHP с таймзоной Europe/Moscow). Тогда отсчёт, серая
кнопка и гейт теста считаются от сервера. Без мета-тега логика
откатывается на часы устройства — только для превью.

Отсчёт работает в три фазы: до 05.11 10:00 – «До начала … осталось»;
с 05.11 10:00 до 08.11 23:59 (мск) – «До конца … осталось» (идёт
диктант); после – финальная фраза «Диктант закончился 08 ноября…».

Гейт кнопки «Принять участие» настраивается разметкой — ничего больше
трогать не нужно:

```html
<a class="btn btn--primary" data-gate="start" href="test.html">Принять участие</a>
```

До старта: серая, без ссылки, + подпись из настроек. После старта:
красная, ведёт на страницу теста. На главной и внутренних страницах
ссылки на тест **отсутствуют до 05.11** — это обеспечивается именно гейтом.

Тренировочные тесты — аналогично `data-gate="training"` на секции;
карточки с `data-cat="school|student|adult"` сами становятся ссылками.

## 5. Серверная часть (API-контракты)

Фронт написан так: если API отвечает — работает бой, если нет —
демо-режим (только для превью, в бою демо-файлы удалить).

### 5.1. Выдача теста — `GET /api/test?cat=school|student|adult|training`

Ответ:
```json
{
  "attemptId": "uuid-попытки",
  "questions": [
    {
      "id": "a01",
      "type": "single | multi",
      "tag": "История",
      "q": "Текст вопроса",
      "media": { "kind": "image", "src": "…jpg|png", "alt": "…" }
                // или { "kind": "video", "src": "…mp4 (H.264)",
                //        "poster": "…", "alt": "…" }
      ,
      "opts": ["вариант 1", "вариант 2", "вариант 3", "вариант 4"]
    }
  ]
}
```
Требования (ТЗ):
- банк каждой категории — **не менее ~50 вопросов**, из них случайно
  выбираются **30**;
- порядок вопросов и вариантов перемешивается **на сервере** при выдаче
  (у соседних участников разные билеты — антисписывание);
- **правильные ответы из JSON исключены** — клиент их не получает
  никогда. Демо-банк с ответами лежит в `question-bank-demo.js`
  и в бой **не выкладывается**;
- вопросы могут содержать изображение (jpg/png) или видео (mp4 H.264).

### 5.2. Подсчёт балла — `POST /api/test/submit`

```json
== запрос ==
{ "attemptId": "uuid", "cat": "school",
  "answers": [[0], [1,3], [2], …] }        // индексы выбранных вариантов по каждому из 30
== ответ ==
{ "score": 27, "max": 30 }
```
Сервер сверяет ответы с банком и возвращает только балл. Разбор
«правильно/неправильно» по требованию заказчика **не показывается**.

Вердикты на фронте по шкале: 30 — «Абсолютный победитель!»,
25–29 — «Отличный результат!», 15–24 — «Хорошая работа!»,
0–14 — «Есть куда расти». Тексты — в `test.js` и в
`docs-dev/documents/Контент-предложения … .docx`.

### 5.3. Дубль-проверка — `POST /api/check-duplicate`

```json
== запрос ==
{ "surname","name","patronymic","sex","age","region","orgType","org",
  "category" }
== ответ ==
{ "duplicate": true | false }
```
Дубль — **точное** совпадение всех перечисленных полей
(ФИО + пол + возраст + регион + организация + категория).
При `true` фронт показывает окно «Вы уже участвовали?» с возможностью
для пользователя подтвердить регистрацию другого человека — повторное
прохождение теста с одного устройства разрешено требованием заказчика.

### 5.4. Регистрация — `POST /api/register`

```json
== запрос ==
{ "surname","name","patronymic","sex","age","email","region","orgType",
  "org","category","score": 27, "total": 30 }
== ответ ==
{ "ok": true, "regNumber": "ПА/НОТА-26/000123" }
```
- `regNumber` = `ПА/НОТА-26/` + ID участника из базы с добивкой нулями
  слева до 6 знаков.
- **Анонимная запись результата (заказчик, 08.08.2026):** если участник
  на экране результата нажал «Отказаться» или не ответил за 2 минуты,
  фронт отправляет тот же endpoint с `variant: "anonymous"`, а вместо
  ФИО и почты — строку «не заполнено». Такую запись хранить в общей
  базе, но сертификат по ней НЕ высылать.
- После регистрации ставится задача отправки сертификата на e-mail
  **в течение 48 часов** (см. раздел 6).
- Согласие на обработку и распространение ПДн обязательно (152-ФЗ);
  DOCX согласий лежат в `assets/docs/` (имена файлов русские, как в
  официальных документах заказчика) и должны быть доступны по
  ссылкам формы.

### 5.5. Справочник организаций — `GET /api/orgs?q=…&region=…`

Ответ: `[{ "n": "полное название", "r": "регион", "s": "краткое" }, …]`
топ-40 по релевантности (до 05.08.2026 был топ-7; увеличено по запросу
заказчика, окно списка на клиенте прокручивается). Логика нечёткого
поиска (токенизация, опечатки) уже написана в `reg-form.js` — её можно
перенести на сервер как есть (это простой скоринг по токенам, без
внешних зависимостей). Нюансы ранжирования: регион участника получает
бонус; записи без графы «регион», в названии которых встречается регион
участника (филиалы РАНХиГС и т.п.), приравниваются к своим — реализация
в блоке «маркеры региона» того же файла.
Полный справочник — выгрузка оргкомитета (~240 тыс. организаций).

## 7. Редакционные правила (уже зашиты, соблюдать в контенте)

1. Обращение к пользователю — «Вы» с большой буквы.
2. Тире в текстах — среднее «–» (не длинное «—»), middot «·» не
   использовать.
3. Буква «ё» — обязательна.
4. Даты диктанта всегда с пометкой «по московскому времени»:
   5 ноября 10:00 – 8 ноября 23:59.
5. «РФ» в текстах не использовать — «Российской Федерации» / «России».
6. Предлоги не отрываются от следующего слова — на сайте это делает
   `typograf.js` автоматически; в контенте CMS желательно ставить
   обычные пробелы, склейку он выполнит сам.

## 8. Запуск локально

```bash
cd site && python3 -m http.server 8901
# http://127.0.0.1:8901/
```

Для проверки состояний «до старта / идёт диктант / после финиша»
добавьте в `<head>` тестовый мета-тег времени (например,
`<meta name="server-time" content="2026-11-06T12:00:00+03:00">`).
