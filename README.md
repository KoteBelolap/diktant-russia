# Сайт Всероссийского гражданско-патриотического диктанта
## «Моя любовь, душа моя — Россия!» · V сезон · 2026

Ссылка на сайт: https://kotebelolap.github.io/diktant-2026/
Статический фронтенд, готовый к продакшену: чистый семантический HTML, современный CSS
(без сборщиков и зависимостей), ванильный JS. Работает с любого подкаталога
(`file://`, `/diktant/`, `/diktant-russia/` — все пути относительные).

## 2. Что уже реализовано по ТЗ

- **Дизайн-токены** платформы: `#0b3041 #205e98 #c00000 #cfe8f9 #62bae3 #d2af3e #3b7d23`,
  светлое оформление, стекло (frosted glass), шрифты Unbounded + Manrope из бренд-пакета.
- **Адаптивность**: брейкпоинты 1440 / 1240 / 1023 / 767 / 480. На <1024px боковое меню
  превращается в топбар с бургер-шторкой. Крупные кликабельные элементы (≥56px) в тесте.
- **Таймер** обратного отсчёта до 06.11.2026 10:00 (МСК) — `main.js`, константа `TARGET`.
- **Интеллектуальный поиск организации** (глава 2 ТЗ): токенизация названий в слова
  нижнего регистра (включая аббревиатурные варианты: МБОУ СОШ ↔ школа …), совпадение
  токенов запроса + нечёткое сравнение с толерантностью к опечаткам (расстояние
  Левенштейна ≤ 2), ранжирование по максимальному пересечению; организации без региона
  видны во всех регионах; есть вариант «нет в списке» → свободный текст.
- **Тест**: категории «Студент вуза/СПО», «Школьник 5–11 класс», «Закончил обучение»;
  одиночный и множественный выбор; 40 минут; авто-подсчёт; максимум 30 баллов;
  защита от повторного прохождения (localStorage + e-mail на бэке); запрет
  копирования/ПКМ; предупреждение при уходе со страницы; экран результата с разбором.
- **Форма регистрации**: ФИО (только буквы), пол, возраст (цифры ≥ 0), e-mail,
  регион (89 субъектов РФ), тип организации (6 вариантов из ТЗ), образовательная
  организация, возрастная категория, два согласия ОПД со ссылками на DOCX из ТЗ.
  После отправки — экран успеха с макетом сертификата.
- **Сертификат**: рендер предоставленного макета (`assets/img/certificate.webp`)
  показан на главной и на экранах успеха; автогенерация PDF — на бэке (см. §3.4).

## 3. Точки интеграции с сервером (что подключить на боевой версии)

### 3.1. Банк вопросов → `assets/js/test.js`
Сейчас тест работает на демо-банке (3 варианта × 10 вопросов) в начале файла —
структура: `{ cat, q, type: 'single'|'multi', options: [...], answer: [индексы] }`.
На боевой версии: заменить `BANKS` на `fetch('/api/test?category=…')`, отдающий
тот же формат **без поля `answer`**; проверку ответов и подсчёт перенести на сервер
(сейчас честно помечено в коде). Таймер и UX менять не нужно.

### 3.2. Регистрация → `assets/js/register.js`
Строка-пометка `имитация отправки на сервер (POST /api/register)` — здесь заменить
имитацию на реальный `fetch` POST формы. Ожидаемый ответ сервера:
`{ ok:true, regNumber:'ПА/НОТА-26/000123' }` — номер подставится в экран успеха.
Сюда же сервер: пишет строку в Excel/БД, обновляет статистику, ставит cookie/e-mail
в список прошедших, инициирует генерацию и отправку PDF-сертификата.

### 3.3. Справочник организаций → `assets/js/orgs-data.js`
Сейчас вшита демо-выборка (~690 записей формата `{"n": название, "c": город, "r": код региона|" "}`).
По ТЗ (глава 2) полный реестр ~67 тыс. записей следует искать **на сервере**:
замените в `register.js` локальный поиск на `fetch('/api/orgs?q=…&region=…')`,
возвращающий топ-N совпадений в том же формате; алгоритм токенизации/нечёткого
сравнения уже реализован на клиенте — переносится один-в-один.

### 3.4. Генерация сертификатов (PDF) — сервер
Макет из бренд-пакета. Требуемые поля: ФИО, возрастная категория, итоговый балл,
регистрационный номер `ПА/НОТА-26/XXXXXX` (6 цифр с ведущими нулями), QR/архивный ID.
Рекомендация: генерировать через headless-шаблон HTML→PDF (wkhtmltopdf/weasyprint)
или по исходному PDF-шаблону с подстановкой полей. Отправка — письмом с темой
«Ваш сертификат участника Диктанта»; архивировать по уникальному ID.

### 3.5. Контент (новости/статьи/видео) → `assets/js/news-data.js`
Три массива с уже боевыми материалами:
- `NEWS_DATA` — 9 новостей (id, date, tag, cover, title, excerpt, body[]);
- `ARTICLES_DATA` — 6 статей (та же структура + `minutes` — время чтения);
- `VIDEOS_DATA` — 6 видеолекций (id, title, speaker, duration, poster, url).
Сейчас `url` — заглушки `#`: подставьте ссылки на видеохостинг/сервер РАНХиГС
(исходные видео 125–650 МБ намеренно не включены в статику — встраивайте плеером).
Страница `article.html` и карточки рендерятся из этих массивов автоматически —
формат полей совпадает с типичной выдачей CMS.

### 3.6. Медиа-карусель на главной
25 оптимизированных фото из архива (`assets/img/media/m*.webp`). Чтобы добавить
видео — вложите в `<figure class="slide">` элемент `<video controls preload="none"
poster="…">` вместо `<img>`: стили и lightbox-логика это поддерживают.

## 4. Деплой

1. Скопируйте содержимое `site/` в `/diktant/` (или `/diktant-russia/`) на веб-сервере
   (nginx/Apache — достаточно статики; специальных заголовков не требуется).
2. MIME-типы: `.webp → image/webp`, `.woff2 → font/woff2` (в свежих nginx уже есть).
3. Включите gzip/brotli и кэширование `assets/*` (immutable, 30 дней).
4. Проверьте, что DOCX-согласия отдаются с `Content-Disposition: attachment` (опционально).
5. Поменяйте одну константу при необходимости: дата старта — `TARGET` в `assets/js/main.js`.

## 5. Доступность и качество

Семантические landmark-элементы, skip-link, `aria`-атрибуты у интерактива, фокус-стили,
`prefers-reduced-motion` (анимации отключаются), контраст текстов ≥ 4.5:1, крупные
тап-зоны. Консоль без ошибок/предупреждений, проверено в Chromium на ширинах
390 / 820 / 1024 / 1440 px.
